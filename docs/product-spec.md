# 我们 · 当前阶段产品规格

版本 1.0 · 2026-09-12

本文收敛原始产品说明与后续讨论，是当前开发范围的统一入口。当前范围包含基础功能、原第二阶段功能、轻互动和时间胶囊。范围更新不代表实现完成；历史架构提案中的阶段划分以本文为准。具体技术方案继续遵循分层架构与既有加密协议。

## 1. 产品目标与开发方式

只服务一对伴侣，每人一个有效设备身份。无需手机号、公开账号、联系人列表或公共内容。产品为 iPhone App，最低部署目标 iOS 18.0，须覆盖用户的 iOS 18.3.2 设备。

先在 Mac 开发并通过独立模拟器完善功能、交互和视觉；再进入真机验收。模拟器完成不等于真实推送、触觉或后台行为已验证。

优先级：隐私、本地优先、亲密感、简洁、可靠性。没有连续签到、未读焦虑、互动排行榜或行为分析。

## 2. 页面结构与视觉方向

四个底部入口固定为：**对话 / 愿望 / 回忆 / 我们**。

| 入口 | 内容 |
| --- | --- |
| 对话 | 唯一伴侣的聊天、媒体、回复、表情回应、轻互动 |
| 愿望 | 愿望生命周期、随机提醒、双人分类清单 |
| 回忆 | 私密时间线、收藏、实现的愿望、时间胶囊 |
| 我们 | 双方资料、关系日期与纪念日、周期、设备和隐私设置 |

整体沿用已生成的暖白、陶土色、柔和绿色概念方向，最终以原生布局、对比度和可访问性为准。统一字体、间距、圆角及图标；支持深色、大字号、小屏、VoiceOver 和减少动态效果。调试控件移入开发入口，不进入正常产品流程。

概念图见 [第一组](design/concepts-v1/README.md) 与 [第二组](design/concepts-v2/README.md)。它们是布局参考，不是可逐像素照搬的最终交互规格；图中头像、照片和日期均为示例。纪念日卡片作为当前设计提案收录，不能用示例数字冒充用户资料。

## 3. 配对与首次使用

- 明确创建或加入一个两人空间，交换公开身份材料，通过二维码与双方核对码建立信任。
- 模拟器支持导入公开载荷或二维码图片；实际摄像头留到真机验收。
- 双方确认后才能进入共享空间；邀请有期限，并提供过期、导入错误、网络中断与重试反馈。
- 重启恢复配对进度；已配对设备保留身份，不要求重复配对。
- 谁记录周期由本人明确选择，伴侣默认只读。通知、相册和麦克风在相应功能使用时说明并申请。
- 隐私页展示实际配对设备与验证状态。身份变化必须显式重新核验，不能静默信任新设备。
- 提供解除配对入口与清楚后果说明；不得暗示解除能远程抹去伴侣已保存的副本。换机、备份恢复方案单列后续，不自动清空本地数据。

## 4. 对话与媒体

- 文字聊天，支持长文本、多行编辑、合理的键盘与滚动行为。
- 图片、短视频和语音：选择/录制、预览、发送、接收、播放；支持取消或重试传输。
- 回复指定消息；轻量表情回应可添加、更换和撤回，与独立轻互动分开。
- 可将消息或媒体收藏为共享回忆，明确标示“加入共同回忆”，避免误以为是私有收藏。
- 每条发送项区分本地待发送、发送中、已送达和等待重试。上传中继不是送达；只有接收方持久化后的加密回执才可标记送达。当前不增加已读压力或在线追踪。
- 媒体设备间加密传输，每个文件独立随机密钥，通过受保护会话传递；本地媒体与缓存加密。中继不托管媒体文件。
- 对方离线或无法建立连接时，显示“等待安全传输”，不显示虚假进度或已送达。连接建立并传输数据后才显示实际进度。
- NAT 穿透与断线续传属于需要实现和验证的传输能力；不能把同一 Mac 的联通当作异地 P2P 成功。如需 TURN 等临时转发，应另记基础设施决策，保持无媒体持久存储。
- 图片默认不进入系统相册；仅用户主动保存时导出。

## 5. 独立轻互动

入口放在聊天输入区附近，首批为“想你了 / 抱抱 / 辛苦啦”。它们是加密的短期互动事件，**不生成聊天气泡、不进入回忆、不累计未读数量**。

| 接收场景 | 行为 |
| --- | --- |
| App 前台 | 短暂动画和可关闭的轻柔触觉；减少动态效果开启时使用静态提示 |
| 后台或锁屏 | 经 APNs 显示通知，可提供“抱回去”等对应操作；是否声音或震动遵循系统与接收方设置 |
| 暂时离线 | 在有效期内尽力送达；过期不补发，不在重启后集中播放 |

前台触觉可设计不同节奏；后台不能承诺指定震动节奏、强制震动或突破专注模式。默认锁屏文案为“收到一份小心意”，具体类型保持加密；如允许显示具体内容，应由接收方主动选择并在设备端解密，失败时回退通用文案。

接收方可关闭轻互动通知或触觉。重复投递只展示一次，连续点击合并；发送方只能显示实际发送/接收状态，不能声称对方手机已震动。

**实施默认值（可调整，并非此前已约定参数）：**有效期 15 分钟，同类互动 10 秒内合并；过期事件退出发送队列。持久化最少去重元数据并按期清理，不保存长期互动历史。通知操作产生新的受限互动，不绕过有效配对与去重规则。

## 6. 愿望与双人清单

愿望创建后立即进入本地发送队列，接收方收到并保存后立即可见；随机提醒不延迟愿望本身的显示。

- 状态：进行中、已实现、以后再说、已归档；双方看到一致结果。完成时间记录为实际用户操作时间。
- 提醒由接收方设备本地选时间，支持未来 1/3/7/30 天及自定义窗口。接收方控制授权、窗口和暂停；发送方及服务器不知道具体提醒时间。
- 通知使用温柔且默认不泄露正文的文案。拒绝通知权限不影响愿望接收与使用。
- 完成、归档或取消相关提醒时撤销待发通知；延期或窗口变动重新规划；重启、重复同步不得重复排程。过期提醒不集中补弹。
- 已实现愿望可进入回忆，并保留来源链接。默认提供“留作回忆”操作；自动加入为可选设置，以稳定来源 ID 防止重复。
- 双人清单位于愿望内，类别为想吃、想去、想看、想买、想做。支持添加、编辑、勾选完成、恢复未完成和删除；完成项可留作回忆。
- 筛选结果严格对应状态；不显示完成百分比、打卡连胜或催促式提示。

## 7. 周期与“我们”

- 周期本人记录开始/结束日期和通常周期长度，展示当前天数与下次日期估算。没有数据时引导录入，不展示伪造预测。
- 本人主要编辑，伴侣只读；日期、预计日期及阶段说明的共享由本人控制。估算不是医疗结论，不用于避孕或生育决策。
- 私人症状、情绪与备注如录入，默认只在本人设备加密保存，不进入共享投影；本轮不增加复杂健康分析。
- 停止共享后同步撤销共享投影；说明无法收回对方已截图或自行保留的信息。
- 关系开始日期与纪念日可由用户填写或编辑，数据为空时不显示概念图里的天数；不引入连续互动计数。
- 设置包括设备验证状态、最近实际同步结果、通知偏好、隐私说明及隐私遮挡。应用锁使用系统认证能力，锁屏保护与触觉最终需要真机确认。

## 8. 回忆

- 共同时间线按年月组织，支持照片、文字记录、收藏消息、实现的愿望、完成的清单和已打开胶囊。
- 可查看详情、补充文字、编辑和删除共享记录；同一来源重复操作不生成多个回忆。
- 来源链接保留可追溯性；来源删除后回忆是否保留内容须明确提示。默认已建立的回忆为独立副本，删除原消息/清单不静默删除回忆，删除回忆也不删除来源。
- 媒体尚未传到本机时显示真实等待状态，不能把可见元数据等同于媒体完整可用。
- 无公开点赞、评论流、用户发现或第三方分享入口；分享至系统相册须用户主动操作。

## 9. 时间胶囊（本轮新增范围）

入口为“回忆 → 时间胶囊”，不新增底部导航。支持文字；图片、短视频、语音随本轮媒体能力接入。

两种形式：一方“写给对方”；“两个人各写一份，到期一起看”。创建时填写标题、内容和开启日期时间，显示接收对象、封存说明与当地时间。

- 状态：草稿 → 已封存/待传输 → 已送达待开启 → 到期可开启 → 已打开；取消作为单独终止状态。媒体传输状态与封存状态分别记录。
- 草稿可编辑；封存后不再原位修改正文和时间，避免双方版本或承诺悄悄变化。本人可在到期前取消自己的一份，再新建；取消需要同步，无法保证离线对方立即获知或擦除既有副本。
- 双人模式双方先约定相同开启时间，各自封存各自内容。到期后允许异步开启，不强制同时在线；只有一方提交也不得无限锁住其内容。界面清楚显示“等待另一份”而不泄露正文。
- 内容提前加密同步，对方正常界面在到期前不能预览正文或媒体；已完整接收后离线也可按设备时间开启。
- 开启时间保存为绝对时间点，展示随当地时区转换；不因旅行或夏令时变动悄悄改变约定时刻。
- 到期可安排接收设备本地通知；没有通知权限仍可在 App 内开启。尚未收到内容时不得提示“内容已可查看”，应显示等待传输。
- 开启动画简短、可跳过，支持减少动态效果；打开后可保留为回忆，重复打开不生成重复回忆或重复提醒。
- **安全边界：这是正常 App 的时间访问限制。**提前把内容和解密材料交给设备后，不能承诺防止修改系统时间、越狱或篡改程序提前读取；不宣传密码学意义的定时解密。服务器不长期保管胶囊或解密密钥。
- 验收包含时间前后调整、时区变化、离线、重启、迟到媒体、取消乱序和双方不同时间打开。

## 10. 隐私、同步与通知的共同约束

- 消息、愿望、周期、清单、回忆、胶囊、轻互动在离开发送设备前加密；私钥不离开设备。使用成熟密码实现，不自行发明算法。
- 长期权威副本在设备；Worker 只承担配对路由、短期密文邮箱、通知与必要 signaling。普通密文邮箱驻留上限 24 小时；轻互动等短期事件使用更短业务有效期。
- 普通业务的中继过期不删除本地权威内容；仍需投递的操作可重试。轻互动过期则停止重试，不能套用永久 outbox 语义。
- 处理离线、重复、乱序、重试和重启；业务对象有稳定 ID，冲突规则可测试。通知、动画、回忆创建和文件提交必须幂等。
- APNs 是通知/唤醒通道，不是可靠队列；前台恢复主动拉取补偿。愿望/胶囊本地通知与轻互动可见远程通知分别接线，不能把静默推送当作保证震动的办法。
- 默认通知载荷不含敏感明文，日志、临时文件和缩略图不得泄露内容；不实现云端历史备份或行为分析。

## 11. 实施批次与完成定义

各批次都包含对应 UI 和测试，不能先堆完业务再把所有可用性问题留到最后。

1. **产品基础**：正式应用入口、配对恢复、消息状态、愿望系统提醒、周期交互、四入口设计组件。
2. **两人日常**：轻互动与通知、引用回复/表情回应、双人清单、纪念日、文字回忆与文字胶囊。
3. **媒体闭环**：加密文件与 P2P、照片/短视频/语音、媒体回忆与胶囊、传输状态与恢复。
4. **整体验收**：网络模式 UI 流程、异常与生命周期、隐私、无障碍、不同屏幕与 iOS 版本、Debug/Release 构建。
5. **真机阶段**：iOS 18.3.2 和另一台目标 iPhone、真实 APNs、后台/锁屏/终止、摄像头、麦克风、生物识别、触觉、性能耗电及异地网络。

Mac/模拟器门槛：范围内正常流程可操作，无正式入口占位页；双独立客户端完整同步；通知权限拒绝可用；重启和离线数据可恢复；媒体异常不误报送达；时间胶囊边界正确；浅深色、大字号、小屏及减少动态效果通过检查。每项保留实际测试证据和待验证事项，不以概念图或脚本调用替代全部 UI 验收。

本地中继、模拟推送、同机 P2P 与公网/真机验证分别记录。模拟器不具备的硬件表现记为待真机，不为赶完成伪造通过。

## 12. 实现现状与不纳入项

当前已建立 SQLCipher/libsignal 核心、Debug 配对、文字/愿望/周期基础事件、HTTP 中继及双模拟器同步。系统通知和正式 Release 等仍未完成；本文件不修改实现状态。历史测试证据见 [真机前验收](pre-device-acceptance.md)。

本轮不包括公开社交、多账号/第三设备、Android、公开 Web、语音视频通话、全文搜索、阅后即焚、消息编辑/撤回、专业健康分析、每日问题或自动随机回忆、密码学强制定时解锁。未指定的媒体大小/时长上限、存储配额、提醒静默窗口等在相应批次根据体验和技术验证设定并记录，不视为无限制承诺。
