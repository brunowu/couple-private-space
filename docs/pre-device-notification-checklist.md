# 真机测试前：通知收敛与验收

更新：2026-09-14。当前 iOS 最低部署版本为 18.0；iOS 18.3.2 可以安装，但锁屏、后台和实际 APNs 投递必须在真机验收。

2026-09-14 现场诊断：保留数据的“我们 · A/B”模拟器均未开启“新消息／小心意”的后台通知开关；仓库中的本地 Worker 没有 APNs 凭据或公网部署配置。向 A 机注入不含真实内容的系统推送时，App 退出后 SpringBoard 正常显示“你有一条新消息”。因此当前缺的是发送端 APNs 投递条件，前台同步后看到抱抱不代表锁屏推送已经接通。

随后已将专用测试 Worker 部署到 `https://couple-private-relay.couple-private-relay.workers.dev` 并验证 `/health`；随机启动口令和 APNs Sandbox 四项配置已作为 Cloudflare Secrets 设置。重新登录 Xcode 后，Debug 真机构建与签名验证通过，描述文件含 `aps-environment=development`。真实投递仍未完成：当前 iPhone 在 CoreDevice 中显示 unavailable，尚需连接、安装、配对并验证锁屏通知。已有 A/B 模拟器配对不能自动迁移到公网地址。

## 已实现的通知入口

| 事件 | 锁屏通用文案 | 触发与打开后去向 |
| --- | --- | --- |
| 新对话／聊天照片 | 你有一条新消息 | 接收方开启后由 APNs 可见推送；打开对话页 |
| 新愿望 | 你有一个新愿望 | 接收方开启后由 APNs 可见推送；打开愿望页 |
| 抱抱／想你了／辛苦啦 | 你收到了一份小心意 | APNs 可见推送；打开 App 验证后可回应 |
| 随机愿望提醒 | 你有一个愿望提醒 | 本机收到并同步愿望后随机排程；打开具体愿望 |
| 时间胶囊到期 | 你有一个时间胶囊提醒 | 本机同步胶囊后按开启时间排程；打开后再验证到期 |
| 纪念日临近／当天 | 有一个重要的日子快到了／今天有一个重要的日子 | 本机按 09:00 排程；打开“我们”的纪念日卡片 |

APNs 只接收“消息／愿望／小心意”这种粗类别，不接收姓名、标题、正文、照片或解密密钥。聊天、新愿望、小心意及本机三类定时提醒可分别关闭；应用内显示的具体内容仍来自本机加密数据库。

## 本地验收门槛

1. Swift 核心测试、Worker 类型检查和测试、Debug/Release iOS 构建通过；用保留配对数据的“我们 · A/B”运行 UI 测试，不要让 Xcode 使用空白模拟器副本。
2. 模拟器上检查允许／拒绝通知、逐类关闭、后台与终止 App 后点通知、改期／删除、跨时区后重新打开 App，以及几种提醒短时间连续到达时的合并。模拟器注入的推送只能验证界面和路由，不能证明真实 APNs 已送达。
3. 检查锁屏文案与 APNs 载荷不出现双方用户名、消息、愿望、纪念日名称、胶囊内容；实际打开 App 后再显示。

## 真机测试启动条件

1. 在 Xcode 为 `private.couple.space.development` 选有效开发团队，App ID 开启 Push Notifications，并确认 Debug 签名有 `aps-environment=development`。
2. 把 Worker 部署到两台手机均可通过蜂窝数据访问的 HTTPS 地址；以部署平台 secret 设置 `APNS_TEAM_ID`、`APNS_KEY_ID`、`APNS_PRIVATE_KEY`、`APNS_TOPIC`，其中 topic 必须等于实际签名 App 的 bundle ID。不要把私钥写进仓库。
3. 两台 iPhone 先在正常网络下完成配对，再分别验证 Wi-Fi／蜂窝、锁屏／后台／重启、通知授权与专注模式、照片聊天、愿望随机时段、胶囊到期、纪念日前几天及当天、抱抱通知与回应。记录 APNs 接收状态和设备上出现时间。

Apple 不保证后台唤醒推送每次及时送达。因此另一台设备新建的胶囊或纪念日，只有在本机同步后才能安排精确到期提醒；可见新愿望推送会尝试后台同步，但随机愿望提醒同样取决于本机是否已同步。锁屏触觉、声音与专注模式由系统和用户设置决定，模拟器不能替代真机验收。[Apple 后台推送说明](https://developer.apple.com/documentation/usernotifications/pushing-background-updates-to-your-app)
