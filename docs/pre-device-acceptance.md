# 真机前开发与验收

更新：2026-09-12。按用户要求，先在 Mac 上开发并使用 iOS 模拟器完善功能、交互和视觉，再安排真机验收。Mac 是开发环境，产品仍为 iPhone App。

范围已随后续讨论扩大到原第二阶段、轻互动和时间胶囊；统一要求及最新实施批次见 [当前产品规格](product-spec.md)。下方实现盘点是扩围前的证据，不代表新增功能已完成。

已有首批功能落地：最新实现与验证结果见 [实现进度](implementation-progress.md)。下方历史盘点中“Release 为占位页”等已被首批实现解决，其余未完成项仍须跟踪。

## 实施顺序

1. 补齐第一版功能闭环：愿望通知、周期交互、配对与异常恢复、消息状态；加入用户提出的轻互动。
2. 完善产品体验：统一颜色、字体、间距和组件；精修聊天、愿望、我们以及首次使用引导。开发调试按钮移到开发入口。
3. 完成工程与模拟器验收：正式 Release 入口、网络模式 UI 回归、兼容布局、权限拒绝、离线与重启恢复。按实际结果记录证据，失败项不得标为完成。
4. 上述阻塞项完成后再安排真机：真实 APNs、锁屏/后台/终止状态、摄像头扫码、生物识别、触觉、实际性能耗电，以及 iOS 18.3.2 与另一台目标 iPhone 的兼容性。

公网中继配置和真实网络验收单独记录；本地 HTTP 成功不代表公网或 APNs 验收成功。

## 范围边界

后续讨论已将图片/P2P、短视频、语音、reaction、回忆、共享清单、轻互动和时间胶囊纳入当前阶段，按产品规格分批实现。旧有第一版检查项仍然适用，但不再代表全部范围；新增模块也必须完成对应的模拟器验收。

## 进入真机阶段的门槛

- 第一版范围内无占位页面、不可用按钮或无法恢复的关键流程。
- 两个独立客户端的业务、权限和离线行为均有验收证据。
- 关键流程通过真实 UI 操作，不仅依赖测试驱动入口。
- 浅深色、大字号和不同尺寸布局完成检查；错误提示可理解且可恢复。
- Debug 和 Release 构建通过；测试工具不暴露给正式用户。
- 所有只能在真机确认的事项明确列为待验证，不承诺模拟器已证明。
